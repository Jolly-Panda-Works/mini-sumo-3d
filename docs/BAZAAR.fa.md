# نسخه‌ی کافه بازار

نسخه‌ی کافه بازار همان بازی است، با این تفاوت‌ها:

- **خرید سکه با پرداخت درون‌برنامه‌ای بازار** (کتابخانه‌ی رسمی Poolakey 2.2.0)
- بدون Google Play Games (ورود با گوگل در پروفایل نمایش داده نمی‌شود)

کد هر دو نسخه یکی است. نسخه‌ی بازار فقط با تنظیمات ساخت فعال می‌شود: `VITE_STORE=bazaar` و اسکریپت `apps/mobile/scripts/bazaar.mjs`.

## ساخت شاخه (یک بار)

```cmd
git checkout main
git pull
git checkout -b bazaar
git push -u origin bazaar
```

هر push روی شاخه‌ی `bazaar` نسخه‌ی بازار را می‌سازد (**Actions ← Bazaar**) و یک Release با تگ `bazaar-vX.Y.Z` منتشر می‌کند.

## به‌روز نگه داشتن

تغییرات همیشه روی `main` انجام می‌شود. برای ساخت نسخه‌ی جدید بازار:

```cmd
git checkout bazaar
git merge main
git push
git checkout main
```

شماره‌ی نسخه و versionCode از `package.json` می‌آید، پس با نسخه‌ی گوگل‌پلی یکسان است.

## تنظیمات

| فایل | محتوا |
|---|---|
| `apps/mobile/bazaar.config.json` | کلید RSA پرداخت درون‌برنامه‌ای، نسخه‌ی Poolakey و Kotlin |
| `apps/client/src/network/bazaarProducts.ts` | شناسه‌ی محصولات بازار برای هر بسته‌ی سکه |

کلید RSA **عمومی** است و فقط برای تأیید امضای خریدها روی گوشی استفاده می‌شود. ثبت آن در مخزن مشکلی ندارد. اگر خواستید جای دیگری نگه دارید، متغیر `BAZAAR_RSA_KEY` در تنظیمات مخزن مقدار فایل را جایگزین می‌کند.

## روند خرید

۱. بازیکن روی **BUY** یک بسته می‌زند. پنجره‌ی پرداخت بازار باز می‌شود و قیمت را خود بازار نشان می‌دهد.
۲. بعد از پرداخت موفق، سکه‌ها به کیف پول گوشی اضافه می‌شوند. هر خرید با شناسه‌ی پرداختش **فقط یک بار** حساب می‌شود.
۳. خرید «مصرف» (consume) می‌شود تا همان بسته دوباره قابل خرید باشد.
۴. اگر برنامه بین پرداخت و افزودن سکه بسته شود، دفعه‌ی بعد که فروشگاه باز شود، خرید ناتمام پیدا و سکه‌اش اضافه می‌شود.

> سکه‌ها روی خود گوشی نگه داشته می‌شوند. برای جلوگیری کامل از تقلب در آینده، تأیید خرید باید روی سرور با API بازار انجام شود (وقتی سرور راه‌اندازی شد).

## امضا

همان secretهای `ANDROID_KEYSTORE_*` نسخه‌ی گوگل‌پلی استفاده می‌شوند. اگر تنظیم نشده باشند، فقط APK دیباگ ساخته می‌شود.


## خرید آنلاین (بررسی خرید روی سرور)

وقتی بازی به سرور وصل است، کیف پول بازیکن روی سرور است. برای همین خرید از کافه بازار این مسیر را طی می‌کند:

۱. بازیکن در کافه بازار پرداخت می‌کند و اپ یک **توکن خرید** می‌گیرد.
۲. اپ توکن را به `POST /api/purchases/bazaar` روی سرور می‌فرستد.
۳. سرور با **Developer API** کافه بازار بررسی می‌کند که خرید **واقعی** است، **مصرف نشده** و مربوط به **همان محصول** است.
۴. سرور سکه‌ها را **یک بار** اضافه می‌کند. هر توکن فقط یک بار، و فقط برای اولین حسابی که آن را بفرستد، پذیرفته می‌شود.
۵. فقط بعد از تأیید سرور، اپ خرید را در کافه بازار **مصرف** می‌کند تا دوباره قابل خرید باشد.

اگر وسط کار مشکلی پیش بیاید (اینترنت قطع شود، سرور یا کافه بازار در دسترس نباشد)، خرید **مصرف نمی‌شود** و دفعه‌ی بعد که بازی وصل شود یا فروشگاه باز شود، دوباره فرستاده می‌شود. هیچ پرداختی گم نمی‌شود.

### راه‌اندازی

سرور خریدها را با «روش جدید» API بازار بررسی می‌کند: فقط **توکن API پیشخان** همان برنامه لازم است (همان توکنی که برای رهانش خودکار در GitHub گذاشته‌اید). کلاینت OAuth و رفرش‌توکن دیگر لازم نیست.

۱. پیشخان بازار ← برنامه ← **API پیشخان بازار** ← «دریافت توکن جدید» (اگر قبلاً گرفته‌اید، همان توکن کافی است).
۲. روی سرور، در پوشه‌ی پروژه: `git pull` و بعد `bash tools/server-bazaar-setup.sh` (توکن را می‌پرسد، از خود سرور با بازار بررسی می‌کند، در `.env` سرور می‌گذارد و بازی را دوباره اجرا می‌کند).
۳. در لاگ سرور (`docker compose logs web`) باید این خط را ببینید:
   `[bazaar] purchase verification on (com.jollypanda.mini_sumo)`

تا وقتی کلیدها روی سرور نباشند، فروشگاه در حالت آنلاین **COMING SOON** نشان می‌دهد و هیچ پولی گرفته نمی‌شود. در حالت آفلاین، خرید مثل قبل روی خود دستگاه ثبت می‌شود.

شناسه‌ی محصولات حالا در `packages/shared/src/economy.ts` (`BAZAAR_PRODUCTS`) است تا اپ و سرور از یک لیست استفاده کنند.

## ورود با بازار

در نسخه‌ی بازار، به‌جای ذخیره با ایمیل، دکمه‌ی **Sign in with Bazaar** در پروفایل هست. ذخیره‌ی بازیکن (حساب سرور بازی، اسم، ظاهر و در صورت جا شدن، پیشرفت روی دستگاه) در «حافظه‌ی درون‌برنامه‌ای بازار» (۱۰ کیلوبایت برای هر کاربر) نگه داشته می‌شود؛ پس روی گوشی تازه یا بعد از نصب دوباره، با ورود به بازار همان بازیکن برمی‌گردد. بازیکنی که قبلاً وارد شده، هنگام شروع بازی خودکار وارد می‌شود.

- اگر بازار نصب نباشد یا قدیمی باشد، صفحه‌ی نصب/به‌روزرسانی خود بازار باز می‌شود.
- اگر کاربر در خود برنامه‌ی بازار وارد نشده باشد (سرویس بررسی وضعیت ورود)، اول به صفحه‌ی ورود بازار فرستاده می‌شود.

## به‌روزرسانی و صفحه‌های بازار

- **بررسی نسخه:** هنگام شروع بازی، از بازار پرسیده می‌شود نسخه‌ی تازه‌تری هست یا نه (BazaarUpdater، بدون نیاز به سرور). دکمه‌ی Update صفحه‌ی به‌روزرسانی بازار را داخل بازی باز می‌کند.
- **به‌روزرسانی خودکار:** اگر خاموش باشد، در About دکمه‌ی **Turn on auto-update** دیده می‌شود.
- **نظر و امتیاز:** About → **Rate & review** صفحه‌ی ثبت نظر بازی در بازار را باز می‌کند.
- **بازی‌های دیگر:** About → **More games** صفحه‌ی برنامه‌های توسعه‌دهنده را باز می‌کند. برای فعال شدنش شناسه‌ی توسعه‌دهنده را از پیشخان بردارید و در `apps/mobile/bazaar.config.json` (کلید `developerId`) یا متغیر مخزن `BAZAAR_DEVELOPER_ID` بگذارید.

## رهانش خودکار در بازار

بعد از هر بیلد موفق شاخه‌ی `bazaar`، APK امضاشده با API پیشخان به بازار فرستاده می‌شود و درخواست بررسی ثبت می‌شود (`tools/pishkhan-release.mjs`).

راه‌اندازی (یک بار):

1. پیشخان بازار ← برنامه ← **API پیشخان بازار** ← «دریافت توکن جدید».
2. GitHub ← Settings ← Secrets and variables ← Actions ← Secrets: `BAZAAR_PISHKHAN_TOKEN` = همان توکن.
3. (اختیاری) Variables:
   - `BAZAAR_AUTO_PUBLISH`: `true` (پیش‌فرض) یعنی بعد از تأیید بازار خودکار منتشر شود؛ `false` یعنی خودتان در پیشخان «انتشار رهانش» را بزنید.
   - `BAZAAR_CHANNEL`: `public` (پیش‌فرض) یا `alpha` (پایین‌تر را ببینید).

نکته‌ها:

- اگر بازار همین versionCode را داشته باشد (اجرای دوباره یا نسخه‌ای که بالا نرفته)، ارسال انجام نمی‌شود.
- یادداشت نسخه **اجباری** است (بخش بعد).
- اجرای دستی workflow روی شاخه‌ای غیر از `bazaar` فقط بیلد می‌گیرد؛ نه GitHub Release می‌سازد و نه به بازار می‌فرستد.

## یادداشت نسخه (اجباری)

هر بیلد بازار، **پیش از ساخت**، یادداشت «تازه‌های این نسخه» را بررسی می‌کند. اگر نباشد، خالی باشد یا برای نسخه‌ی دیگری نوشته شده باشد، بیلد با خطا متوقف می‌شود (چیزی ساخته یا منتشر نمی‌شود).

**با push (معمول):**

1. `main` را در `bazaar` ادغام کنید:
   ```
   git checkout bazaar
   git merge main
   ```
2. فایل `apps/mobile/bazaar-release-notes.json` را **روی شاخه‌ی bazaar** پر کنید:
   ```json
   {
     "version": "1.33.0",
     "fa": "متن فارسی تازه‌ها",
     "en": "What's new in English"
   }
   ```
   `version` باید دقیقاً نسخه‌ی `package.json` باشد. هر متن حداکثر ۱۰۰۰ نویسه.
3. کامیت و push:
   ```
   git commit -am "chore(bazaar): release notes" && git push && git checkout main
   ```
4. بعد از انتشار موفق، GitHub خودش فایل را خالی می‌کند (یک کامیت `[skip ci]` روی `bazaar`)، تا نسخه‌ی بعد بدون یادداشت تازه منتشر نشود. پیش از کار بعدی روی این شاخه `git pull` بزنید.

این فایل را روی `main` ویرایش نکنید؛ فقط روی `bazaar` (وگرنه هنگام ادغام تداخل پیش می‌آید).

**با اجرای دستی** (Actions ← Bazaar ← Run workflow): دو فیلد «What's new, in Persian» و «… in English» اجباری‌اند و جای فایل را می‌گیرند (برای خط جدید `
` بنویسید). در این حالت فایل دست نمی‌خورد.

یادداشت‌ها در درخواست انتشار پیشخان (`changelog_fa` / `changelog_en`) و در GitHub Release نسخه‌ی بازار هم می‌آیند.

## رهانش آلفا

با رهانش آلفا یک نسخه فقط به دست اعضای گروه آلفا (تا ۱۰۰ شماره موبایل) می‌رسد. API پیشخان امکان انتخاب گروه انتشار را ندارد و گروه باید پیش از ارسال درخواست بررسی انتخاب شود؛ برای همین در حالت آلفا، بیلد فقط **به‌صورت پیش‌نویس بارگذاری می‌شود** و انتخاب گروه و ارسال را خودتان در پیشخان انجام می‌دهید.

1. یک بار: پیشخان ← رهانش‌ها ← گروه‌های رهانش ← گروه جدید؛ شماره‌های آزمایش‌کننده‌ها را اضافه کنید.
2. یک نسخه را آلفا بفرستید:
   - فقط همین بار: Actions ← Bazaar ← Run workflow ← شاخه‌ی `bazaar` ← channel: `alpha`؛
   - یا همیشه: متغیر مخزن `BAZAAR_CHANNEL=alpha`.
3. پیشخان ← رهانش‌ها ← مدیریت رهانش‌ها: در رهانشِ پیش‌نویس، گروه انتشار را «آلفا» و گروه خود را انتخاب کنید و درخواست بررسی بدهید.
4. وقتی نسخه آماده‌ی همه شد، در همان‌جا گروه انتشار را به «عمومی» تغییر دهید (برگشت به آلفا ممکن نیست).

تا پیش‌نویسِ همان نسخه در پیشخان باشد، بیلدهای بعدی همان نسخه دوباره فرستاده نمی‌شوند.

## ورود با بازار در وب

در نسخه‌ی وب (مرورگر)، کنار Google Play و ایمیل، دکمه‌ی **Sign in with Bazaar** هم هست. ورود با پروتکل OAuth2 بازار و روی سرور بازی انجام می‌شود: حساب بازار به بازیکن وصل می‌شود و در دستگاه دیگر، ورود با همان حساب بازار همان بازیکن را برمی‌گرداند. شناسه‌ی حساب از سرور بازار می‌آید، پس جعل‌شدنی نیست.

راه‌اندازی (یک بار):

1. پیشخان ← برنامه ← **ورود با بازار**: کلاینت آی‌دی و رمز (secret) را بردارید.
2. در همان صفحه، این آدرس بازگشت را اضافه کنید: `https://sumo.ryujin.fans/api/account/bazaar/callback`
3. روی سرور، در پوشه‌ی پروژه: `bash tools/server-bazaar-login-setup.sh` (مقدارها را در `.env` می‌نویسد و بازی را دوباره راه می‌اندازد).

بعد از آن دکمه خودکار در نسخه‌ی وب (sumo.ryujin.fans و GitHub Pages) ظاهر می‌شود. برای آدرس‌های دیگر بازی، `BAZAAR_LOGIN_RETURN_ORIGINS` را (با کاما) در `.env` سرور بگذارید. نسخه‌ی اندروید بازار از خود برنامه‌ی بازار وارد می‌شود؛ نسخه‌ی دسکتاپ و اندروید گوگل‌پلی این دکمه را ندارند (برگشت از صفحه‌ی بازار به برنامه ممکن نیست).
